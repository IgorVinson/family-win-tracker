# Roadmap

Phases after phase 1 are proposals. They are not approved specs. An agent starts a phase only after the PM puts an approved spec in `docs/plan` and only one phase lands in a pull request against `dev`.

## Phase 0 — Agent tooling

Cursor skills, Cloud Agent install, and these planning docs. No app code. This is the current phase.

## Phase 1 — One family

Approved target, specified in `PROJECT.md`:

- 2 parents and 4 kids, each on a separate device
- parent-provisioned kid access, no kid email signup
- chore with an AI photo check and one-tap parent approval
- points and a reward store

## Proposed phase 2 — Household history

Bring over the useful Family Win Tracker ideas that phase 1 does not need on day one: streaks, goal targets, and a readable history of points and redemptions. Same single family.

## Proposed phase 3 — More than one family

Parent invites for additional families, still with server-assigned roles and family-scoped rules. No shared global kid directory.

## Proposed phase 4 — Retire the legacy app

Remove the Vite + Supabase tree once KidsRise phase 1 is in use and the data that matters has a home in Firebase. Not before.
