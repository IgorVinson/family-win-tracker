# MCP connectors for Cloud Agents

Add these in the Cursor dashboard for this repo's Cloud Agents (Settings → MCP, or the environment's MCP list). This file is an example. Do not commit API keys, tokens, or a live Firebase project id.

Use a **dev Firebase project or the local emulators only**. Do not attach these connectors to production.

## Firebase

Stdio server, from the Firebase CLI:

```json
{
  "mcpServers": {
    "firebase": {
      "command": "npx",
      "args": ["-y", "firebase-tools@latest", "mcp"]
    }
  }
}
```

Command string: `npx -y firebase-tools@latest mcp`.

Before an agent uses it, select a non-production project (`firebase use <dev-project>`) or start the emulators (`firebase emulators:start`) for Auth, Firestore, Storage, and Functions. Login for Cloud Agents is `npx -y firebase-tools@latest login --no-localhost` if the dashboard session has no Firebase credentials yet. Store any token the CLI asks for as an environment secret.

## Expo

HTTP server:

```json
{
  "mcpServers": {
    "expo": {
      "url": "https://mcp.expo.dev/mcp"
    }
  }
}
```

URL: `https://mcp.expo.dev/mcp`.

Complete Expo account auth in the dashboard if the connector asks for it. Do not paste the token into the repo.

## Context7

HTTP server, for current library docs:

```json
{
  "mcpServers": {
    "context7": {
      "url": "https://mcp.context7.com/mcp"
    }
  }
}
```

URL: `https://mcp.context7.com/mcp`.

If Context7 asks for an API key, put that key in the dashboard secret store, not in git.

## Maestro

Stdio server shipped inside the Maestro CLI. The Cloud Agent install script puts `maestro` on `/usr/local/bin` and Java 17 on the login-shell `JAVA_HOME`.

```json
{
  "mcpServers": {
    "maestro": {
      "command": "maestro",
      "args": ["mcp"],
      "env": {
        "JAVA_HOME": "/usr/lib/jvm/java-17-openjdk-amd64"
      }
    }
  }
}
```

Command string: `maestro mcp`.

If the dashboard does not pass `env`, set `JAVA_HOME` to `/usr/lib/jvm/java-17-openjdk-amd64`. The CLI still needs a device or emulator before UI commands can drive the app; installing the CLI does not start an Android emulator.
